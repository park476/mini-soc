# 사용자 결정 기록

기록은 시간순이며, 같은 항목의 현재 상태는 마지막 결정을 따른다. 과거 기록의 미정 표시는 당시 상태다.

## 2026-09-21 — STEP 1 실행 환경 결정

근거: 사용자의 최신 명시적 결정. 같은 요청의 마지막에 지정한 D2 관제 서버 위치까지 반영한다.

아래 항목은 사용자 확정 결정이며 [설계 완료] 상태다. 실제 환경 구축·접속·동작을 확인했다는 의미는 아니다.

| 항목 | 확정 내용 |
|---|---|
| D1. 피해 서버 실행 위치 | 역할·배치 결정 확정: 교수님에게 빌릴 예정인 학교 Ubuntu 미니 PC 서버. 아직 대여되지 않았으며 장비 확보·환경 검증 전 |
| D2. 관제 서버 실행 위치 | 사용자 개인 노트북의 WSL2 Ubuntu 환경 |
| 공격자 환경 | 학교 PC에서 실행하는 WSL Kali Linux |
| 공격 수행 범위 | 졸업 프로젝트의 통제된 실습·시연 범위에서만 수행 |

D1과 D2는 실행 위치에 대한 결정이다. 이 최초 기록 시점에는 D3 피해/관제 서버 격리 방식, D4 로그 전달 기술, 실제 로그 위치 또는 수집 Source를 비롯한 나머지 미결정 사항을 확정하지 않았다. D3의 최신 상태는 아래 추가 결정을 따른다.

현재 단계는 STEP 1이며, STEP 2로 진행하지 않는다.

## 2026-09-21 — STEP 1 DB 분리 및 격리 방향 추가 결정

근거: 사용자의 최신 명시적 결정. 아래 확정 내용은 문서상 결정이며 실제 구축·연결·동작 확인을 의미하지 않는다.

### 실행 환경 재확인

- 공격자: 학교 PC에서 실행하는 WSL Kali Linux.
- D1 피해 서버: 교수님에게 빌릴 예정인 학교 Ubuntu 미니 PC 서버로 역할·배치를 결정했다. 아직 사용자에게 대여되지 않았으며, 장비 확보·접속·네트워크 연결·로그 위치·동작 여부는 확인하지 않았다. 2026-09-22 교수님께 장비 대여를 요청할 예정이다. 구현 완료·구축 완료·동작 확인을 의미하지 않는다.
- D2 관제 서버: 사용자 개인 노트북의 WSL2 Ubuntu 환경.
- 공격은 졸업 프로젝트의 통제된 실습·시연 범위에서만 수행한다.

### DB 분리 — 확정

- 피해 서버와 관제 서버는 하나의 PostgreSQL DB를 공유하지 않는다.
- 관제 서버는 자체 PostgreSQL에 정규화된 보안 이벤트와 탐지·분석·대응 결과를 저장한다.
- 피해 웹서비스 DB는 필수로 확정하지 않는다. D21 피해 웹서비스 로그인/DB 필요 여부는 [결정 필요]로 유지한다.
- 피해 웹서비스 DB를 두더라도 관제 DB와 공유하지 않는다.

### D3 격리 방향 — 방향 확정, 세부 수준은 결정 필요

- 공격자·피해 서버·관제 서버를 서로 다른 실행 환경에 배치한다.
- 피해 시스템 데이터와 관제 데이터를 논리적으로 분리한다.
- 관제 서버가 피해 서버의 로컬 로그 파일이나 DB를 직접 공유·마운트해서 읽는 구조를 기본 전제로 하지 않는다.
- 로그는 피해 서버에서 관제 서버로 네트워크를 통해 전달한다.
- VLAN, 별도 서브넷 등 네트워크 수준의 세부 격리 방식은 아직 확정하지 않는다. 실제 학교 네트워크 연결 환경을 확인한 뒤 D3의 세부 격리 수준을 확정한다.

### 과거 구조도·구두 답변과의 관계

- 사용자 설명에 따르면 이전 교수님 제출용 구성도에는 피해 서버 DB와 관제 PostgreSQL이 별도로 표현되어 있었다. 이번 작업에서 과거 구성도 자체를 확인한 것은 아니다.
- 과거 대화에서 “같은 DB 공유”라고 답변한 적이 있더라도 현재 최신 결정은 DB 비공유 구조다.
- 최신 사용자 결정이 과거 구두 답변보다 우선한다. 과거 구성도에 피해 DB가 있다는 사실만으로 D21을 확정하지 않는다.

### 자동 대응 흐름 재확인

- 자동 대응은 상관분석이나 보안 사고 생성을 필수 선행 조건으로 하지 않는다.
- 경보 또는 필요한 탐지 결과가 자동 대응 조건을 만족하면 별도 흐름으로 실행할 수 있다.
- 구체적인 자동 대응 발동 조건과 IP 차단 구현 기술을 이번 결정으로 확정하지 않는다.

### 계속 미정인 항목

D3의 세부 네트워크 격리 수준, D4 로그 전달 기술, D14 IP 차단 구현 기술, D21 피해 웹서비스 로그인/DB 필요 여부 및 그 밖의 기존 미결정 사항은 이 기록 시점에는 유지했다. Filebeat, rsyslog, Python 전달기, UFW, iptables, nftables 중 어느 것도 당시 선택하지 않았다.

현재 단계는 STEP 1이며, STEP 2로 진행하지 않는다.

## 2026-09-21 — STEP 1 최소 구현안 사용자 결정

사용자가 제시한 최소 구현안을 최신 설계 결정으로 기록한다. 이전 기록의 해당 미정 상태를 대체한다. 기술 선택과 수치 지정은 실제 구축·테스트 완료를 의미하지 않는다. D1은 여전히 장비 대여·확보 전이며 D2와 공격자 배치는 유지한다.

PRD가 실제 테스트 후 결정하도록 남겼던 SSH 수치와 자동 해제 정책은 이번 사용자 결정으로 설계값을 지정했다. 실제 테스트 결과는 아직 없으며, 검증 후 변경이 필요하면 사용자에게 보고한다. PRD 자체는 수정하지 않는다.

| ID | 최신 설계 결정 |
|---|---|
| D3 | 공격자·피해·관제는 서로 다른 장비. 같은 학교 LAN 사용 가능. VLAN·별도 서브넷은 만들지 않음 |
| D4 | 피해 서버 rsyslog 사용. Nginx access.log는 imfile로 읽고 SSH 인증 로그도 rsyslog로 전달. TCP 5514로 관제 서버 Python 수집기가 수신 |
| D5 | Nginx 스캔: 동일 IP가 60초 안에 404/403 응답을 발생시키며 서로 다른 URI를 10개 이상 요청하면 탐지 |
| D6 | Nginx 의심 경로 접근: /.env, /wp-admin, /admin 등 사전 정의한 민감·탐색 경로 접근 탐지 |
| D7·D8 | 같은 출발지 IP에서 SSH 무차별 대입 경보와 Nginx 스캔 또는 의심 경로 경보가 10분 이내 함께 발생하면 상관분석 성립 |
| D9·D10 | 0~100 점수와 Low/Medium/High 표시. SSH brute force 40, Nginx scan 30, suspicious path 20, 위 상관분석 성립 시 +30, 최대 100 |
| D11 | 상관분석 성립 및 위험도 High(70 이상)이면 Incident 생성. Alert와 Incident 분리 |
| D12 | 동일 IP에서 60초 안에 SSH 인증 실패 5회 이상 |
| D13 | SSH brute force Alert 생성 시 자동 대응 조건 충족. 상관분석·Incident를 기다리지 않으며 D15의 차단 제외 적용 |
| D14 | 관제 서버에서 피해 서버로 SSH 원격 명령 실행. 피해 서버 UFW로 공격자 IP의 SSH 접근 차단 |
| D15 | 관제 서버 IP와 시스템 관리에 필요한 주소를 차단 제외. 공격자 Kali IP는 제외하지 않음 |
| D16 | 자동 해제 기능 없음. 시연·테스트 종료 후 관리자가 수동 해제 |
| D17 | 차단 후 동일 Kali에서 피해 서버 SSH 재접속. 실제 접속 실패 여부를 별도 기록 |
| D18 | 실행 결과와 실제 효과 검증 결과를 분리 저장 |
| D19 | 마지막 로그 수신 시각과 수신 오류 기록. 일정 시간 로그가 없으면 전달 이상을 확인할 수 있게 함 |
| D20 | 원본 로그와 실패 이유를 별도 정규화 실패 기록으로 보존 |
| D21 | 피해 웹 로그인·DB를 만들지 않음. Nginx 로그 생성용 최소 웹 서비스만 사용. 피해 서버 DB 없음 |
| D22 | 실제 통제 실습에서 생성한 예비 로그를 보관하고 동일 파서·탐지 흐름으로 재처리. 예비 로그 재생으로 실제 IP 차단 성공을 주장하지 않음 |

### 남은 세부 결정과 실제 검증

- D4: 실제 로그 위치·형식, TCP 메시지 경계·전달 형식, 학교 LAN에서 노트북 WSL2 수집기까지의 연결 가능 여부는 확인 전이다.
- D5·D6: URI 구분·정규화 방식, 의심 경로 전체 목록과 일치 방식은 미정이다.
- D8~D10: 경보의 시간 기준, 점수 집계 대상·기간·반복 경보 중복 계산 방식, Low/Medium 경계는 미정이다. High는 70 이상으로 지정되었다.
- D14·D15: 원격 실행 권한·실제 SSH 포트·허용 목록의 구체적 IP는 확인·설계가 필요하다.
- D17: 재접속 실패 기록은 실제 차단 검증의 입력이다. 인증 실패나 서비스·네트워크 장애와 차단 효과를 구분하는 구체적 판정 근거는 후속 설계에서 정한다. 단순 접속 실패만으로 차단 성공을 단정하지 않는다.
- D18~D20: 저장 스키마, 무수신 시간 기준과 확인 단위는 미정이다. 무수신 상태만으로 전달 실패 원인을 확정하지 않는다.
- 기존 E1~E5의 데이터·API·화면·예외 정책 등 후속 설계와 실제 검증은 남아 있다.

STEP 1 사용자 결정 기록 상태이며 STEP 2나 구현으로 자동 진행하지 않는다.

## 2026-09-21 — STEP 1 남은 사용자 결정 확정 및 재검토

사용자의 최신 결정으로 아래 사항을 확정한다. 앞선 기록의 해당 미정 표시는 이 결정으로 대체한다.

| 항목 | 확정 내용 |
|---|---|
| D9 위험도 등급 | Low 0~39, Medium 40~69, High 70~100 |
| D10 점수 집계 | 현재 판단 대상 안에서 탐지 종류별 기본 점수를 1회만 반영. SSH brute force 40, Nginx scan 30, suspicious path 20, 지정 상관분석 성립 시 +30, 최대 100. 같은 종류의 반복 Alert를 발생 횟수만큼 누적하지 않음 |
| D6 초기 의심 경로 | /.env, /wp-admin, /wp-login.php, /admin, /phpmyadmin, /.git, /config, /backup |
| D6 일치 기준 | query string을 제외한 URL path가 목록의 경로와 정확히 일치하거나 해당 경로의 하위 경로이면 탐지 |
| D19 무수신 기준 | 초기 설계값 60초. 전달 이상 표시 기준이며 장애 원인을 확정하지 않음. 실제 피해 서버 환경 검증 후 필요하면 변경 가능 |
| D17 실제 차단 검증 | UFW에 대상 IP 차단 규칙이 실제 등록되었는지 확인하고 동일 공격자 Kali에서 피해 서버 SSH 재접속. 규칙 존재와 해당 환경의 SSH 접속 실패를 함께 확인해야 검증 성공으로 기록. 단순 접속 실패만으로 성공 판정하지 않음 |

위험도 판단 대상 기간과 구현 데이터 구조는 STEP 4에서 정의한다. 데이터 스키마·API 명세·화면 구조 및 기타 구현 세부 사항은 후속 STEP의 설계 항목이며 STEP 1에서 추가 사용자 결정이 필요한 항목으로 취급하지 않는다.

장비 확보, 실제 학교 LAN·WSL2 연결, 실제 로그 위치·형식, 포트·IP·권한 및 동작 확인은 [검증 예정]이다. 특히 D1은 장비 대여·확보 전이라는 상태를 유지한다. 이 상태는 역할·배치 설계 결정 미완료를 뜻하지 않는다.

재검토 결과: F1~F6 요구사항과 STEP 1 사용자 결정 정리를 완료했다. 현재 STEP 1에서 추가로 필요한 사용자 결정은 없다. STEP 1 완료는 후속 상세 설계나 구현·검증 완료, READY TO CODE 판정이 아니다. STEP 2는 진행 가능한 상태이나 사용자의 진행 지시 전에는 시작하지 않는다.
