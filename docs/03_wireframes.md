# STEP 3 — 최소 화면 와이어프레임

기준: [PRD](PRD.md), [최신 결정](00_decisions.md), [요구사항](01_requirements.md), [사용자 흐름·화면](02_flow_screens.md). 아래 `<값>`은 배치 설명용 자리이며 실제 데이터가 아니다. 목록에서 선택하면 같은 화면 아래의 상세가 바뀐다. 별도 상세 페이지를 만들지 않는다.

## A. 관제 대시보드

```text
+------------------------------------------------------------------+
| 소형 보안관제 시스템                                              |
| [A 관제] [B 보안 이벤트] [C 경보/보안 사고] [D 자동 대응]           |
+------------------------------------------------------------------+
| 로그 수신 상태                                                   |
| 마지막 수신: <시각>   상태: <수신 상태/전달 이상/확인 불가>         |
| 수신 오류: <기록 또는 없음>                                       |
| 60초 무수신: 전달 이상 표시 기준, 장애 원인 확정 아님              |
+------------------------------------------------------------------+
| 최근 이벤트                                        [B 목록 보기] |
| 로그 종류 | 발생 시각 | 출발지 IP | 행동/결과 | [상세 -> B]        |
| <기록>                                                           |
+------------------------------------------------------------------+
| 최근 Alert / Incident                              [C 목록 보기] |
| 구분 | 발생 시각 | 출발지 IP | 탐지 규칙/연관 규칙 | [상세 -> C]   |
| <기록>                                                           |
+------------------------------------------------------------------+
| 최근 자동 대응                                     [D 목록 보기] |
| 대상 IP | 발동 Alert | 실행 결과 | 실제 검증 상태 | [상세 -> D]    |
| <기록>                                                           |
+------------------------------------------------------------------+
```

수신 상태를 먼저 보고 최근 기록에서 근거 화면으로 이동한다. 자동 대응 요약에서도 실행 결과와 실제 검증 상태를 합치지 않는다.

## B. 보안 이벤트 목록/상세

```text
+------------------------------------------------------------------+
| [A 관제] [B 보안 이벤트] [C 경보/보안 사고] [D 자동 대응]           |
+------------------------------------------------------------------+
| 이벤트 목록                                                      |
| 선택 | 로그 종류 | 발생 시각 | 출발지 IP | 행동/결과              |
| [ ]  | <Nginx/SSH> | <시각>  | <IP>      | <행동/결과>            |
+------------------------------------------------------------------+
| 선택 이벤트 상세                                                 |
| 로그 종류: <값>   발생 시각: <값>   출발지 IP: <값>                |
| 행동/결과: <값>                                                  |
| 근거 항목: <실제 기록의 인증 결과 또는 URI/응답 코드 등>           |
| 원본 로그 근거                                                   |
| <선택 이벤트에 연결된 원본 로그>                                  |
| [연결해 온 경보로 돌아가기 -> C]                                  |
+------------------------------------------------------------------+
| 정규화 실패 기록                                                 |
| 선택 | <실패 기록> | 실패 이유                                    |
| [ ]  | <기록>      | <이유>                                       |
| 선택 실패 기록: <원본 로그>                                       |
| 실패 이유: <값>                                                  |
+------------------------------------------------------------------+
```

정상 이벤트와 정규화 실패 기록은 분리된 영역에 둔다. 실패 기록을 선택해도 성공한 SecurityEvent로 표시하지 않는다. 상세 미선택 시 선택 안내를 표시하며, C에서 진입했다면 해당 근거 이벤트를 선택한다.

## C. 경보·보안 사고 목록/상세

```text
+------------------------------------------------------------------+
| [A 관제] [B 보안 이벤트] [C 경보/보안 사고] [D 자동 대응]           |
+------------------------------------------------------------------+
| [Alert 목록] [Incident 목록]                                      |
| 선택 | 구분 | 탐지 규칙/연관 규칙 | 출발지 IP | 발생 시각          |
| [ ]  | <값> | <규칙>              | <IP>      | <시각>             |
+------------------------------------------------------------------+
| 선택 항목 상세: <Alert / Incident>                                |
| 탐지 규칙: <규칙 및 적용 조건>                                    |
| 출발지 IP: <값>   발생 시각: <값>                                 |
| 관련 이벤트: <근거 항목> [원본 근거 -> B]                          |
+------------------------------------------------------------------+
| 상관분석 결과: <성립/불성립/결과 없음>                             |
| 연결된 Alert: <규칙, 출발지 IP, 시각> [같은 화면에서 선택]         |
| 연결 근거: <동일 IP 및 10분 이내 조건의 실제 기록>                 |
| 위험도: <점수>/100  <Low / Medium / High>                          |
| 점수 근거: <종류별 1회 반영 점수 및 상관분석 가산>                 |
| Incident 구분 근거: <상관분석 성립 및 High 조건 확인 결과>         |
+------------------------------------------------------------------+
| 대응 기록: <관련 기록 또는 없음> [실행/검증 근거 -> D]             |
+------------------------------------------------------------------+
```

Alert와 Incident는 같은 화면의 목록 전환으로 구분한다. Incident의 규칙 정보는 연관 Alert를 통해 보여준다. 결과 없음은 불성립이나 위험도 0과 다르다. 위험도는 Low 0~39, Medium 40~69, High 70~100이며 기록된 계산 근거를 함께 표시한다.

## D. 자동 대응 결과/검증

```text
+------------------------------------------------------------------+
| [A 관제] [B 보안 이벤트] [C 경보/보안 사고] [D 자동 대응]           |
+------------------------------------------------------------------+
| 대응 기록 목록                                                   |
| 선택 | 발동 Alert | 대상 IP | 실행 결과 | 실제 검증 상태           |
| [ ]  | <경보>     | <IP>    | <결과>    | <상태>                   |
+------------------------------------------------------------------+
| 선택 대응 상세                                                   |
| 발동 Alert: <SSH brute force 경보> [발동 근거 -> C]                |
| 대상 IP: <값>                                                    |
| 허용 목록 판정: <차단 제외/제외 아님/확인 불가>                    |
| 판정 근거: <기록된 이유>                                          |
+------------------------------------------------------------------+
| 1. 실행 결과: <성공/실패/미실행/확인 불가>                         |
|    <기록된 실행 결과 또는 실패 이유>                              |
+------------------------------------------------------------------+
| 2. 실제 효과 검증 근거                                           |
| UFW 대상 IP 차단 규칙: <존재 확인/미존재/미확인>                   |
| 동일 Kali SSH 재접속: <접속 실패/접속 성공/미확인>                 |
| <각 확인 결과의 기록된 근거>                                      |
| 실제 검증 상태: <성공/실패/미검증>                                |
+------------------------------------------------------------------+
```

실행 결과와 효과 검증을 위아래 별도 영역으로 배치한다. 대상 IP의 UFW 차단 규칙 존재와 동일 Kali의 SSH 재접속 실패가 함께 확인돼야 검증 성공이다. 미검증을 실패나 성공으로 대신 표시하지 않는다. 차단 제외는 실행 성공이 아니다. 실행·승인·공격·편집·해제 버튼은 두지 않는다.

## 화면 간 이동 관계

```text
공통 메뉴: A <-> B <-> C <-> D (어느 화면에서든 각 화면으로 이동)

A 최근 이벤트 ---------> B 해당 이벤트 상세
A 최근 Alert/Incident -> C 해당 경보/보안 사고 상세
A 최근 자동 대응 ------> D 해당 대응 상세

C 관련 이벤트 ---------> B 원본 근거 --[돌아가기]--> C 진입 항목
C 관련 Alert ----------> C 같은 화면에서 해당 Alert 선택
C 대응 기록 -----------> D 해당 대응 상세
D 발동 Alert ----------> C 발동 경보 --[관련 이벤트]--> B
```

발표에서는 A의 수신 현황, B의 원본·이벤트, C의 탐지·분석 근거, D의 실행·검증 근거 순서로 설명한다. 화면 이동 순서는 백엔드 실행 순서가 아니다. 자동 대응은 화면 클릭이나 대시보드 가동에 의존하지 않으며 상관분석·Incident 생성을 기다리지 않는다.

## 공통 상태 표시

| 상태 | 표시와 적용 원칙 |
|---|---|
| 로딩 | 조회하는 목록·상세 영역에 `불러오는 중` 표시. 결과를 임의로 0·성공으로 채우지 않음 |
| 빈 데이터 | 조회 성공 후 기록이 없을 때 `기록 없음`. 미선택 상세에는 `목록에서 항목을 선택하세요` 표시 |
| 조회 오류 | `기록을 불러오지 못했습니다`와 조회 재시도 제공. 시스템 탐지·차단 실패나 빈 목록과 구분 |
| 미검증 | D의 검증 미수행·근거 미확인 시 `미검증`. 실행 성공이어도 검증 성공으로 바꾸지 않음 |

각 영역의 상태는 독립적으로 표시한다. 분석 결과 미확인은 불성립과 구분하고, 필수 근거가 조회되지 않았다면 확인 불가로 표시한다. 상태 이름은 화면 표시 의미이며 DB 상태값을 여기서 확정하지 않는다. Mock UI는 참고자료이며 실제 데이터 조회·검증 완료로 취급하지 않는다.

## STEP 4 데이터 항목 연결 메모

조회 구조는 `React -> Django/DRF -> PostgreSQL`을 유지한다. 화면은 API가 제공하는 실제 기록을 사용하며 React가 DB에 직접 접근하지 않는다. 아래는 후속 설계에 필요한 연결 메모만이며 데이터 스키마·API 명세 설계를 시작한 것이 아니다.

| 화면/영역 | 필요한 데이터와 연결 |
|---|---|
| A 로그 수신 | 마지막 수신 시각, 수신 오류, 초기 60초 무수신에 따른 전달 이상 상태. 무수신으로 장애 원인을 확정하지 않음 |
| A 최근 기록 | B의 이벤트, C의 Alert/Incident, D의 대응 기록에서 가져온 요약과 해당 상세를 여는 참조 |
| B 이벤트 | SecurityEvent의 로그 종류·발생 시각·출발지 IP·행동/결과, 실제 탐지 근거 항목, 원본 로그 또는 원본 참조 |
| B 정규화 실패 | 실패 원본 로그와 실패 이유. 정상 이벤트와 구분할 연결 |
| C Alert | 규칙·적용 조건·IP·시각, 관련 SecurityEvent 참조 |
| C 분석/Incident | 연관 Alert, 상관분석 결과·근거, 위험도 점수·등급·종류별 반영 내역, Incident 구분 근거. 판단 대상 기간·구조는 STEP 4에서 정의 |
| C-D 연결 | 경보와 대응 기록의 관계. Incident가 없어도 발동 Alert에서 대응 근거에 접근 가능 |
| D 실행/검증 | 발동 Alert, 대상 IP, 허용 목록 판정·이유, 실행 결과, UFW 규칙 확인, 동일 Kali 재접속 결과, 실제 검증 상태 및 근거. 실행과 검증을 분리 저장·조회 |

새 사용자 결정이 필요한 항목은 없다. STEP 3의 정보 배치·화면 이동 설계는 완료했으며 STEP 4는 시작하지 않았다.
